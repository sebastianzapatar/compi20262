Curso de Compiladores

Construyendo un Intérprete desde Cero

Descubre las entrañas de los lenguajes de programación creando el tuyo propio usando Go. Todo explicado de forma clara para que no te pierdas en el código.

1. ¿Qué es un Intérprete?

El Traductor de Código

Un intérprete es un programa informático capaz de analizar y ejecutar otros programas. A diferencia de un compilador (que traduce todo el código a lenguaje máquina antes de ejecutarlo), el intérprete traduce y ejecuta el código línea por línea o instrucción por instrucción.

Lenguajes muy famosos como Python, JavaScript y Ruby funcionan mediante intérpretes por debajo. Construir el nuestro nos enseñará cómo las computadoras realmente entienden el texto que escribimos.

2. Arquitectura General

Todo el viaje del código fuente desde texto plano hasta su ejecución se divide en una "tubería" (pipeline) de tres fases fuertemente conectadas.

El Flujo de Vida

  1. Lexer: Recibe texto y escupe Tokens.
  2. Parser: Recibe Tokens y escupe un Árbol (AST).
  3. Evaluador: Recorre el Árbol y ejecuta las acciones (suma, resta, asignación).

¿Por qué separar las fases?

¡Para mantener la cordura! Intentar evaluar el código directamente desde el texto plano implicaría lidiar con espacios, saltos de línea y precedencia matemática todo al mismo tiempo. Al dividirlo, cada parte hace una sola cosa muy bien.

3. El Lexer (Análisis Léxico) y los Tokens

Transformando texto en significado

El código fuente no es más que una cadena larga de caracteres. El trabajo del Lexer es leer esa cadena, carácter por carácter, e identificar qué partes forman "palabras" con significado. A estas palabras las llamamos Tokens.

Entrada (Código Fuente)

let edad = 5;

El lexer ignora los espacios en blanco de forma automática para simplificar el proceso posterior.

Salida (Lista de Tokens)

[
  {Type: LET, Literal: "let"},
  {Type: IDENT, Literal: "edad"},
  {Type: ASSIGN, Literal: "="},
  {Type: INT, Literal: "5"},
  {Type: SEMICOLON, Literal: ";"}
]

4. El Parser y el Árbol de Sintaxis Abstracta (AST)

Tener una lista de Tokens está muy bien, pero una lista plana no tiene estructura. Necesitamos entender quién depende de quién.

¿Qué es el AST?

El Abstract Syntax Tree es una estructura de datos jerárquica (un árbol en programación) que representa de forma precisa la estructura lógica del código. "Abstracta" porque omite detalles sintácticos irrelevantes como llaves, puntos y comas o paréntesis (el árbol en sí mismo ya da el orden jerárquico).

¿Qué hace el Parser?

  • Consume la lista de tokens generada por el Lexer.
  • Verifica que la gramática sea correcta. (¡Aquí es donde te da el famoso Error de Sintaxis si olvidas cerrar un paréntesis!).
  • Aplica la precedencia de operadores. Sabe que en 5 + 5 * 2, la multiplicación va primero y debe estar más abajo en el árbol.

Ejemplo de Árbol

Para la sentencia let x = 10;, el AST se vería así:

LetStatement {
  Name: Identifier("x"),
  Value: IntegerLiteral(10)
}

5. El Evaluador y el Entorno

Haciendo que la magia ocurra

Una vez que tenemos nuestro hermoso Árbol AST, necesitamos recorrerlo. El Evaluador es una función recursiva que visita cada nodo del árbol, de abajo hacia arriba, calculando resultados.

El Entorno (Environment)

Para manejar variables como let a = 10;, el evaluador necesita memoria. El "Environment" es simplemente un Diccionario (un mapa/hashmap en Go) que guarda asociaciones de nombres y valores.

// Así se ve conceptualmente el Entorno:
map[string]Object {
  "x": IntegerObject(10),
  "y": BooleanObject(true),
}

6. La Consola Interactiva (REPL)

Read, Eval, Print, Loop

El REPL es el programa principal que unifica todas las piezas. Funciona en un ciclo infinito:

  • Read: Lee lo que el usuario escribe en la consola.
  • Eval: Le pasa el texto al Lexer, luego al Parser, y finalmente al Evaluator.
  • Print: Imprime el Objeto resultante en la pantalla para que el usuario lo vea.
  • Loop: Imprime el prompt >> y vuelve a esperar.

¡Limón te espera!

En CatCompiler, Limón el gato es tu anfitrión en el REPL. Él se asegura de que tus tokens sean procesados y te acompaña cuando ejecutas go run main.go.

7. Estructura de Módulos (Go)

Así es como se conectan las carpetas y paquetes de nuestro proyecto a nivel de código.

Paquetes de Datos

  • token: Las "palabras" base (ej. LET, INT). Es el bloque más pequeño. No depende de nadie.
  • ast: El Árbol de Sintaxis Abstracta (ej. LetStatement, IfExpression). Representa la estructura de lo que programamos.
  • object: El Sistema de Tipos real del evaluador (ej. Objetos que guardan números enteros o booleanos en memoria).

Paquetes Activos (Motores)

  • lexer: Transforma un string en elementos del paquete token.
  • parser: Toma los tokens generados por el lexer y ensambla la estructura definida en ast.
  • evaluator: Recorre el ast, realiza los cálculos reales y genera resultados del tipo object.
  • repl / main: Orquestan el show. Toman el texto, lo pasan al lexer, luego al parser, y finalmente al evaluador.
