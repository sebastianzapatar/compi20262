Construyendo un Intérprete desde Cero

Una guía visual y detallada para entender cómo funcionan los lenguajes de programación por dentro. Escrito en Go, explicado para humanos.

1. ¿Qué es un Intérprete?

El Traductor Simultáneo de Código

Un intérprete es un programa que lee, analiza y ejecuta otros programas. A diferencia de un compilador (que traduce todo el código a lenguaje máquina antes de ejecutarlo), un intérprete procesa el código instrucción por instrucción, ejecutándolo sobre la marcha.

Lenguajes como Python, JavaScript y Ruby usan intérpretes por debajo. Construir el nuestro nos enseña cómo una computadora realmente "entiende" el texto que escribimos.

Compilador vs Intérprete

  • Compilador: Traduce TODO el código antes de ejecutar. Produce un ejecutable. Ejemplo: C, Go, Rust.
  • Intérprete: Lee y ejecuta línea por línea. No produce un ejecutable separado. Ejemplo: Python, Ruby.

¿Qué construiremos?

Un intérprete llamado CatCompiler escrito en Go que soporta:

  • Variables (let x = 5;)
  • Aritmética (5 + 3 * 2)
  • Funciones (function(x) { return x; })
  • Condicionales (if/else)
  • Ciclos (while, for)

2. Arquitectura General

El viaje del código fuente desde texto plano hasta su ejecución se divide en una tubería (pipeline) de transformaciones secuenciales. Cada fase toma la salida de la anterior como entrada.

💡 ¿Por qué separar las fases?
Intentar hacer todo al mismo tiempo sería un caos. Al dividirlo, cada parte hace una sola cosa muy bien. El Lexer no se preocupa por las matemáticas, el Parser no se preocupa por los espacios en blanco, y el Evaluador no se preocupa por la gramática. Esto hace que el código sea más fácil de entender, probar y mantener.

3. Los Tokens

Los tokens son las "palabras" más pequeñas de nuestro lenguaje. Son la unidad mínima con significado, como las palabras en el español.

¿Qué es un Token?

Cada Token es una estructura simple con dos campos:

  • Type → Qué tipo de pieza es (número, operador, palabra reservada...)
  • Literal → El texto original tal como apareció en el código
// Definición de un Token en Go:
type Token struct {
    Type    TokenType  // Ej: "INT", "LET", "PLUS"
    Literal string     // Ej: "42",  "let", "+"
}

4. El Lexer (Análisis Léxico)

El Lexer es el primer paso del pipeline. Toma el código fuente como un string y lo convierte en una secuencia de Tokens.

📥 Entrada (Código Fuente)

let edad = 5 + 3;

Para el Lexer, esto es solo una cadena de caracteres: l, e, t, , e, d, ...

📤 Salida (Lista de Tokens)

{Type: LET,       Literal: "let"}
{Type: IDENT,     Literal: "edad"}
{Type: ASSIGN,    Literal: "="}
{Type: INT,       Literal: "5"}
{Type: PLUS,      Literal: "+"}
{Type: INT,       Literal: "3"}
{Type: SEMICOLON, Literal: ";"}

¿Cómo funciona internamente?

El Lexer usa 4 campos para moverse por el código fuente:

  • input → El string completo del código fuente.
  • position → La posición del carácter que estamos leyendo AHORA.
  • readPosition → La posición del SIGUIENTE carácter (para "espiar" adelante).
  • ch → El carácter actual bajo análisis.

Funciones clave:

Función¿Qué hace?

5. El AST (Árbol de Sintaxis Abstracta)

El AST es una estructura jerárquica que representa el significado lógico del código. Convierte una lista plana de tokens en un árbol con relaciones padre-hijo.

¿Por qué un árbol y no una lista?

Una lista plana no tiene estructura. Si tenemos los tokens [5, +, 3, *, 2], no sabemos si es (5+3)*2 o 5+(3*2). El árbol resuelve esto poniendo las operaciones prioritarias más abajo (se resuelven primero).

// "5 + 3 * 2" se convierte en:
//
//       InfixExpression(+)
//       /               \
//   IntLiteral(5)    InfixExpression(*)
//                    /               \
//               IntLiteral(3)    IntLiteral(2)
//
// El evaluador recorre de abajo hacia arriba:
// Primero resuelve 3 * 2 = 6, luego 5 + 6 = 11

Las 3 Categorías del AST

🔵 Nodo (Node)

La base. Todo en el árbol es un Nodo. Define los métodos TokenLiteral() y String().

🟣 Sentencia (Statement)

Instrucciones que no producen un valor. Ej: let x = 5;, return 10;

🟢 Expresión (Expression)

Código que sí produce un valor. Ej: 5 + 3, miVar, true

6. El Parser y el Algoritmo Pratt

El Parser toma la lista de tokens del Lexer y construye el Árbol AST. Usa el algoritmo Pratt Parsing (Top-Down Operator Precedence) para resolver correctamente la jerarquía matemática.

La Idea Central de Pratt Parsing

Cada token tiene un nivel de prioridad (precedencia). El parser usa dos diccionarios:

  • prefixParseFns → Funciones para tokens al INICIO de una expresión (ej. un número 5, una negación -x, un if).
  • infixParseFns → Funciones para tokens EN MEDIO de una expresión (ej. +, *, ==).

Cuando el parser encuentra un token, busca la función correspondiente en el diccionario y la ejecuta. Es como tener un especialista para cada tipo de operación.

⚖️ Tabla de Precedencias (Prioridad)

Un número más alto = se agrupa PRIMERO en el árbol.

🎬 Ejemplo Paso a Paso: 1 + 2 * 3

Tokens: [INT(1), PLUS(+), INT(2), ASTERISK(*), INT(3)]

LLAMADA 1: parseExpression(LOWEST=1)
  → Ve INT(1) → crea IntegerLiteral(1) como leftExp
  → peek = PLUS(+), precedencia = SUM(4). Como 1 < 4, ENTRA al loop
  → Avanza al +. Llama a parseInfixExpression(left=1)
    → Guarda Left=1, Op="+", prioridad actual=SUM(4)
    → Necesita el Right → llama recursivamente parseExpression(SUM=4)

    LLAMADA 2: parseExpression(SUM=4)
      → Ve INT(2) → crea IntegerLiteral(2)
      → peek = ASTERISK(*), precedencia = PRODUCT(5). Como 4 < 5, ENTRA al loop
      → Avanza al *. Llama a parseInfixExpression(left=2)
        → Guarda Left=2, Op="*", prioridad=PRODUCT(5)
        → Necesita el Right → llama recursivamente parseExpression(PRODUCT=5)

        LLAMADA 3: parseExpression(PRODUCT=5)
          → Ve INT(3) → crea IntegerLiteral(3)
          → peek = EOF, precedencia = LOWEST(1). Como 5 > 1, NO entra al loop
          → Retorna IntegerLiteral(3)

      → Right = 3 → Retorna InfixExpression(2, "*", 3)

  → Right = (2 * 3) → Retorna InfixExpression(1, "+", (2 * 3))

RESULTADO FINAL: (1 + (2 * 3))  ✅ ¡La multiplicación se agrupó primero!

7. El Evaluador

El Evaluador es la última fase: toma el Árbol AST y lo ejecuta, produciendo resultados reales.

¿Cómo funciona?

Es una función recursiva llamada Eval(node) que recorre el árbol de abajo hacia arriba:

  • Si el nodo es un IntegerLiteral(5) → devuelve el objeto entero 5.
  • Si el nodo es un InfixExpression(3, "+", 2) → evalúa Left (3), evalúa Right (2), suma ambos → devuelve 5.
  • Si el nodo es un LetStatement("x", 5) → guarda x=5 en el entorno (memoria).
  • Si el nodo es un IfExpression → evalúa la condición, y según sea true/false ejecuta el bloque correspondiente.

🧠 El Entorno (Environment)

Para que las variables funcionen, el evaluador necesita memoria. El "Environment" es un diccionario que guarda las asociaciones nombre → valor:

// Conceptualmente, el Entorno es un mapa:
Environment = map[string]Object{
    "x":      IntegerObject(10),
    "nombre": StringObject("Limón"),
    "activo": BooleanObject(true),
}

Cuando el evaluador encuentra un Identifier("x"), busca "x" en el Environment y devuelve su valor (10).

9. La Consola Interactiva (REPL)

Read → Eval → Print → Loop

El REPL es el programa principal que unifica todas las piezas en un ciclo infinito:

  1. Read: Lee lo que el usuario escribe en la consola.
  2. Eval: Pasa el texto por el Lexer → Parser → (futuro: Evaluador).
  3. Print: Muestra el resultado al usuario.
  4. Loop: Vuelve al paso 1 mostrando el prompt >>.

🎮 CatCompiler tiene dos modos

Al iniciar con go run main.go, el usuario puede elegir:

  • Modo 1 (Lexer): Muestra la lista de tokens generados por el Lexer.
  • Modo 2 (Parser): Muestra el AST reconstruido como texto (con paréntesis de precedencia).
$ go run main.go
Selecciona el modo de interacción:
1. Modo Lexer (Muestra los Tokens generados)
2. Modo Parser (Construye y muestra el Árbol AST)
Opción [1 o 2]: 2

>> let x = 3 + 4 * 41;
AST Generado: 
let x = (3 + (4 * 41));

📦 Paquetes de Datos (Estructuras)

  • token/ → Las "palabras" base del lenguaje. No depende de nadie.
  • ast/ → Las estructuras del árbol (LetStatement, IfExpression...). Depende de token.
  • object/ → Los valores reales en memoria (Integer, Boolean, Null).

⚙️ Paquetes Activos (Motores)

  • lexer/ → Transforma string en []token.
  • parser/ → Transforma []token en ast.Program.
  • evaluator/ → Transforma ast.Program en object.
  • repl/ + main.go → Orquestan todo el flujo.
