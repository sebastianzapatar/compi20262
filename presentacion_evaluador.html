Construyendo el Evaluador

La guía definitiva para entender cómo un lenguaje de programación cobra vida. Explicación profunda de Objetos, Closures, Scopes y Recursividad en Go.

🎯 ¿Cuál es la misión del Evaluador?

Hasta ahora, el Lexer convirtió el texto en Tokens, y el Parser organizó esos Tokens en un Árbol (AST). Pero el AST es solo una estructura de datos inerte. Es un mapa, no el viaje.

El Evaluador (o Intérprete Tree-Walking) es el motor que lee ese árbol, nodo por nodo, y le dice al procesador de tu computadora qué hacer: sumar números reales, asignar memoria real, e imprimir resultados reales.

1 El Sistema de Objetos (Memoria Real)

Antes de poder evaluar algo, necesitamos definir cómo se representan los valores en memoria durante la ejecución del programa. El AST tiene ast.IntegerLiteral, pero eso es solo la representación sintáctica del código fuente. Cuando el programa corre, necesita un valor real.

La Interfaz Object

En Go, obligamos a que todos los valores de CatCompiler (números, booleanos, funciones) cumplan con una interfaz fundamental:

type ObjectType string

type Object interface {
    Type() ObjectType  // Ejemplo: devuelve "INTEGER"
    Inspect() string   // Ejemplo: devuelve "42" para imprimir en consola
}
Integer

Envuelve un número de Go en nuestra propia estructura para manejarlo con seguridad.

type Integer struct {
    Value int64
}
Boolean

Usamos un patrón Singleton: solo creamos TRUE y FALSE una vez en memoria para optimizar.

type Boolean struct {
    Value bool
}
Null

Representa la ausencia de valor (útil cuando una función no retorna nada).

type Null struct{}

2 La Función Gigante: Eval()

El núcleo de todo el evaluador es una sola función recursiva escrita en evaluator.go. Su trabajo es recibir cualquier Nodo del AST y devolver un object.Object.

El Switch Case Maestro

La función Eval usa un switch basado en el tipo de Nodo que está leyendo (Type Assertion de Go).

func Eval(node ast.Node, env *object.Environment) object.Object {
    switch node := node.(type) {
    
    // 1. Si es un número pelado, lo convertimos a Objeto
    case *ast.IntegerLiteral:
        return &object.Integer{Value: node.Value}
        
    // 2. Si es una suma (ej. 5 + 3)
    case *ast.InfixExpression:
        left := Eval(node.Left, env)   // Recursividad: evalúa el 5
        right := Eval(node.Right, env) // Recursividad: evalúa el 3
        return evalInfixExpression(node.Operator, left, right)
        
    // 3. Si es un IF
    case *ast.IfExpression:
        return evalIfExpression(node, env)
        
    // ... y así con cada tipo de nodo
    }
    return nil
}

🔍 Anatomía de la Evaluación (Recursividad)

Para evaluar 5 + (10 * 2), el Evaluador desciende por las ramas del árbol hasta encontrar valores literales, y luego sube combinándolos.

Eval( InfixExpression: "+" )
↓ Llama a evaluar la Izquierda
Eval( IntegerLiteral: 5 ) 👉 Retorna Integer(5)
↓ Llama a evaluar la Derecha
Eval( InfixExpression: "*" )
Eval( 10 ) 👉 Retorna Integer(10)
Eval( 2 ) 👉 Retorna Integer(2)
↑ Sube multiplicando (10 * 2)
Retorna Integer(20)
↑ Sube sumando (5 + 20)
Resultado Final: Integer(25)

3 Environment (La Memoria y Variables)

Si el código fuera solo matemáticas puras, no necesitaríamos memoria. Pero tenemos variables. Cuando ejecutamos let edad = 20;, ese 20 tiene que guardarse en algún lado.

¿Qué es el Entorno?

Es un Mapa (Diccionario) que relaciona nombres (strings) con Valores (Objects).

type Environment struct {
    store map[string]Object
    outer *Environment
}

Cuando Eval encuentra let x = 5; llama a env.Set("x", 5). Cuando encuentra x + 2, llama a env.Get("x").

El Puntero outer (Scopes)

¿Qué pasa si declaramos una variable dentro de un if? No queremos sobreescribir las variables globales. Para esto, creamos un Environment "Hijo".

Si el evaluador busca la variable "x" en el hijo y no la encuentra, sigue el puntero outer y la busca en el padre.

4 El Poder de las Funciones (Closures)

Esta es la parte más compleja pero más hermosa de construir un intérprete. En CatCompiler, las funciones son objetos de primera clase (First-Class Citizens). Eso significa que se guardan en variables, se pasan como argumentos y se devuelven, igual que un número.

1. Creación de la Función

Cuando Evaluador encuentra let sumar = function(a, b) { return a + b; }, crea en la memoria un objeto de tipo Function que guarda 3 cosas:

  • Parameters: La lista [a, b]
  • Body: El código AST de las sumas.
  • Env: El entorno EXACTO donde fue creada. Esto es lo que permite los Closures (funciones que "recuerdan" el contexto exterior aunque se ejecuten en otro lado).

2. Llamando a la Función (CallExpression)

Cuando hacemos sumar(5, 3), ocurre esta secuencia de eventos críticos en applyFunction():

Paso¿Qué pasa en Go?
1Se evalúan los argumentos 5 y 3 (pasan a ser Objetos).
2Se crea un Nuevo Environment (hijo del Environment guardado en la función).
3Se inyectan los parámetros al nuevo environment: env.Set("a", 5) y env.Set("b", 3).
4Se llama a Eval() pasándole el Cuerpo de la Función y este Nuevo Environment.
5Al terminar, el Nuevo Environment se destruye, protegiendo las variables globales.

5 El Truco del Return

En Go o Java, cuando llamas a return, sales de la función actual. Pero en nuestro evaluador, todo el código es un gran ciclo for que procesa AST.

function(x) {
  if (x > 5) {
    return true; // ¡Debe detener todo!
  }
  return false; // Esto no debería ejecutarse si x > 5
}

¿Cómo detener el AST? El evaluador envuelve el valor retornado en un object.ReturnValue. Cuando la función padre (ej: `evalBlockStatement`) ve que un nodo hijo devolvió un `ReturnValue`, deja de procesar la siguiente línea de código y propaga ese valor hacia arriba, rompiendo el ciclo exitosamente.

6 Control de Flujo y Ciclos

Tener estructuras de control en tu lenguaje no requiere magia profunda, ¡solo requiere usar las estructuras de control del lenguaje en el que lo estás construyendo (Go)!

Condicional If

1. Evalúa la condición.
2. Verifica si el objeto resultante es Verdadero (Truthy).
3. Si es verdadero, evalúa el AST de la consecuencia. Si no, el de la alternativa (else).

Ciclo While / For

Usamos un ciclo for {} infinito en Go. En cada vuelta, evalúa la condición. Si es falsa, hacemos break de Go. Si es verdadera, evaluamos el cuerpo del AST.
