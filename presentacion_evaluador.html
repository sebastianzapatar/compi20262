Comprendiendo el Evaluador

Una inmersión profunda al corazón de CatCompiler. Desde cómo la memoria (Environment) actúa como hojas de acetato transparente, hasta cómo los Closures cargan "mochilas" de variables en el tiempo.

🎯 ¿Cuál es la misión del Evaluador?

Hasta ahora, el Lexer convirtió el texto en Tokens, y el Parser organizó esos Tokens en un Árbol (AST). Pero el AST es solo una estructura de datos inerte. Es el plano de una casa, no la casa en sí.

El Evaluador (Intérprete Tree-Walking) es el obrero que lee ese plano, nodo por nodo, y le dice al procesador de tu computadora qué hacer: sumar números, asignar memoria, e imprimir resultados. Transforma la sintaxis abstracta en semántica viva.

1 El Sistema de Objetos (Memoria Real)

Antes de poder sumar o comparar, necesitamos definir cómo se representan los valores en la RAM de la computadora durante la ejecución. El AST tiene el nodo ast.IntegerLiteral, pero eso es solo sintaxis. Cuando el programa corre, necesita un "Objeto" que pueda manipularse, sumarse y pasarse a funciones.

La Interfaz Object

En el archivo object/object.go definimos una interfaz que TODO valor en CatCompiler debe cumplir para existir en memoria. Debe saber qué tipo es, y debe saber cómo imprimirse a sí mismo.

type ObjectType string

type Object interface {
    Type() ObjectType  // Devuelve la etiqueta, ej: "INTEGER"
    Inspect() string   // Lo que se muestra en consola, ej: "42"
}
Integer

Envuelve el tipo primitivo int64 de Go dentro de nuestra propia estructura.

type Integer struct {
    Value int64
}
Boolean

Truco de optimización: Solo creamos TRUE y FALSE una única vez en todo el sistema y reciclamos esos punteros.

type Boolean struct {
    Value bool
}
Function

¡Una función es un objeto más! Se puede guardar en variables y devolver.

type Function struct {
    Parameters []*ast.Identifier
    Body       *ast.BlockStatement
    Env        *Environment
}

2 La Función Gigante: Eval()

El núcleo del evaluador es una sola función recursiva escrita en evaluator.go. Usa un Switch Type inmenso para saber en qué tipo de nodo del AST estamos parados y decidir qué hacer con él.

El Switch Maestro

func Eval(node ast.Node, env *object.Environment) object.Object {
    switch node := node.(type) {
    
    // 1. ¿Es un número pelado en el AST? Lo convertimos a Objeto de Memoria
    case *ast.IntegerLiteral:
        return &object.Integer{Value: node.Value}
        
    // 2. ¿Es una Operación Binaria? (ej. 5 + 3)
    case *ast.InfixExpression:
        // ¡LA RECURSIVIDAD EN ACCIÓN!
        left := Eval(node.Left, env)   // Baja y resuelve el 5
        right := Eval(node.Right, env) // Baja y resuelve el 3
        
        // Ahora que tenemos los objetos evaluados, los sumamos en Go
        return evalInfixExpression(node.Operator, left, right)
        
    // 3. ¿Es una declaración Let? (ej. let x = 5)
    case *ast.LetStatement:
        val := Eval(node.Value, env)   // Evalúa lo que está a la derecha del =
        env.Set(node.Name.Value, val)  // Lo guarda en la memoria
        
    // ... y así con cada nodo del lenguaje
    }
    return nil
}

🔬 Lupa: ¿Cómo suma exactamente evalInfixExpression?

Cuando tenemos left y right listos, llamamos a un helper. Este helper extrae el número "real" de Go, lo suma, y vuelve a empaquetarlo en un Objeto para CatCompiler.

func evalIntegerInfixExpression(operator string, left, right object.Object) object.Object {
    // 1. Extraemos los valores int64 primitivos de Go
    leftVal := left.(*object.Integer).Value
    rightVal := right.(*object.Integer).Value

    // 2. Operamos y repaquetamos en el Objeto de CatCompiler
    switch operator {
    case "+":
        return &object.Integer{Value: leftVal + rightVal}
    case "*":
        return &object.Integer{Value: leftVal * rightVal}
    // ...
    }
}

3 Environment (La Memoria y Variables)

Para poder recordar variables necesitamos un Environment. En programación, un Environment no es más que una tabla Hash (un diccionario o mapa) que vincula nombres de variables (Strings) con Valores en memoria (Objects).

¿Cómo es en Código?

Usamos un map[string]Object en Go. Cuando Evaluador lee let edad = 20; llama a Set("edad", 20). Cuando luego encuentra la palabra edad en el código, llama a Get("edad").

type Environment struct {
    store map[string]Object
    outer *Environment
}

El Puntero outer (Scopes)

Imagina que declaras una variable dentro de un if o una función. ¡No queremos ensuciar el entorno global! Para ello creamos un Environment "Hijo".

💡 La Analogía de las Hojas de Acetato:

Imagina el Environment como hojas transparentes apiladas. Estás mirando desde arriba. Dibujas la variable "x" en la hoja superior (el scope local). Si buscas "x", la ves inmediatamente. Si buscas "y" y no está en la hoja superior, tu vista traspasa la hoja transparente y mira la hoja de abajo (el outer scope). Así hasta llegar a la hoja base (variables globales).

4 Closures y Funciones: La Magia Pura

Esta es la característica de diseño de lenguajes que divide a los principiantes de los expertos. En CatCompiler, las funciones pueden "recordar" variables de donde nacieron, incluso si se ejecutan en otro lugar o tiempo. Esto se llama Closure.

La Mochila de Supervivencia 🎒

Cuando el Evaluador encuentra la declaración de una función (function(x){...}), crea un Objeto Función. Lo fascinante es el campo Env: La función guarda un puntero exacto al Environment que existía en el milisegundo en que ella nació. Es como si armara una mochila con el estado del mundo para llevársela puesta.

let crearContador = function() {
    let cuenta = 0;
    return function() { // ¡Esta función nace adentro!
        let cuenta = cuenta + 1;
        return cuenta;
    };
};

let miContador = crearContador();
miContador(); // Devuelve 1
miContador(); // Devuelve 2  <-- ¡Recordó y modificó la 'cuenta' original!

El Proceso de Llamar una Función (CallExpression)

Cuando finalmente ejecutas miContador(), ocurren 5 pasos quirúrgicos en applyFunction():

  1. Se evalúan los argumentos (si pasaste (5, 3), se vuelven objetos).
  2. Se fabrica una hoja de acetato nueva (Environment hijo). ¿Quién es el padre de esta hoja? ¡El entorno que la función traía en su mochila (el outer)!
  3. Se inyectan los argumentos en esta hoja nueva. Si la función recibe a y b, se hace Set("a", 5) y Set("b", 3) en el hijo.
  4. Se llama recursivamente a Eval() pasándole el Cuerpo de la Función y esta hoja nueva.
  5. Al terminar el bloque, la hoja nueva (el entorno hijo) se descarta, y las variables globales quedan protegidas.

5 El Truco del Return

En lenguajes compilados, un `return` manipula el registro del procesador para saltar a otra dirección de memoria. Pero nosotros estamos corriendo un ciclo for en Go leyendo árboles. ¿Cómo simulamos que la ejecución se detenga instantáneamente si estamos en medio de 5 bloques anidados?

El Problema

if (true) {
    if (true) {
        return 100; // ¡Debe matar a todos los padres!
    }
    // ESTO NUNCA DEBERÍA EVALUARSE
    let x = 50; 
}

La Solución: El Objeto ReturnValue

El evaluador no hace saltos, en vez de eso "envuelve" el número `100` en un escudo llamado object.ReturnValue.

Cuando la función `evalBlockStatement` está ejecutando línea por línea y ve que el resultado de la línea anterior fue de tipo ReturnValue, rompe su propio ciclo for inmediatamente y pasa el escudo hacia el bloque superior, provocando un efecto dominó que desenreda el árbol instantáneamente.
